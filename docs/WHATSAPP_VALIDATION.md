# WhatsApp API 验证记录

核验日期：2026-10-18。状态：代码准备完成、模拟验证通过；真实平台未接入，通道默认关闭。

## 本次发布的验证

在 warehouse-system 发布副本中，从仓库目录包恢复公开数据后运行 `python -m pytest -q --tb=short`：**190 passed**（15.51秒）。其中 **9项 WhatsApp 专项测试通过**。输出存在既有依赖/日期API弃用警告，无测试失败。

先前开发工作区的195项测试还包含未纳入本次WhatsApp发布的5项公开目录网关测试；本记录以此次发布文件集合的190项结果为准。

首次运行因发布副本的一份旧生成校验文件与目录包不同而未能恢复完整数据，导致46项目录相关测试失败；备份差异文件并恢复仓库原始目录包后，190项全部通过。没有修改业务服务数据来使测试通过。

## WhatsApp 专项覆盖

| 场景 | 验证结果 |
|---|---|
| 默认关闭、错误/过期签名、错误渠道、群聊 | 拒绝调用 |
| 管理员预登记本组织技师，手机号与绑定码匹配 | 正确身份激活，其他号码不能兑换 |
| 一次性码及重放 | 新事件不能重复兑换，原事件重试安全 |
| 本组织工单、跨组织查询和反馈用料 | 本组织可读，其他组织记录/零件被拒绝 |
| 反馈草稿及明确确认 | 草稿不写报告，错误确认文字不提交 |
| 反馈重复/不同消息ID重复确认/并发确认 | 只生成一份报告和一份提交审计 |
| 领取版本变更、其他用户草稿、停用和撤销 | 拒绝写入或调用 |
| 服务重启、主库已提交后适配器中断 | 重试恢复结果，不重复创建报告 |
| 草稿到期、撤销后重绑、旧事件与旧设备 | 到期拒绝，旧事件不能用于新绑定，不接管旧设备工单 |
| 新报告影响维修建议 | 保持pending，未审核不成为正向指导 |

所有身份、组织、工单与消息均为隔离测试数据。测试不发送真实WhatsApp消息、不登录真实技师账户、不调用付费服务。

## 当前边界

- 签名为自定义服务端适配契约，不是已实现Meta原生Webhook验签。
- API响应提供reply_to；delivery_status仍为not_sent，没有真实自动回复。
- 独立服务入口 `scripts.whatsapp_adapter:app` 默认禁用，没有挂载到当前主服务或公开隧道。
- 当前主服务和公开目录网关的WhatsApp events路径均核实为404。
- 本次未修改前端、服务启动配置、域名或云资源；未开通付费服务。
- 本文记录本地发布副本测试，GitHub CI结果请查看PR检查，不将未完成的CI标为通过。

## 可复现步骤

在隔离开发/CI环境安装requirements.txt后执行：

```sh
python -m scripts.install_catalog_bundle
python -m pytest tests/test_whatsapp_adapter.py -q
python -m pytest -q
```

目录包安装器拒绝覆盖不同内容。应使用干净checkout，或先备份本地生成文件，不要覆盖业务数据库。测试使用独立测试库。
